01요약

  1. 데모는 실제 서버로 돕니다. 회원 진입 검증, 구매 적립, 확정, 코인 전환, 재시도, 월간 지급 내역까지 데모 저장소(pricepick-demo)의 서버 코드가 처리합니다.
  2. 규칙은 한 파일에 모았습니다. api/_lib/asp.js 를 운영 서버로 옮기면 됩니다. 탑툰 쪽 동작만 흉내 서버(api/asp-mock)가 대신하고, 이것은 옮기지 않습니다.
  3. 시험 24건(node tests/asp/run.js)이 연동 문서 08의 8가지를 포함합니다. 운영 코드도 같은 시험을 통과해야 합니다.
  4. 운영으로 갈 때 바꿀 곳은 08절 12개입니다. 포스트백 연결, 확정 배치, 1분 재시도 스케줄러, 토큰·세션 비밀값, 데모 장치 끄기가 핵심입니다.

02데모 주소

화면주소용도
시연 화면/asp-sim/탑툰 회원을 골라 무료충전소에서 들어가는 것부터 재현합니다. 왼쪽은 탑툰 흉내 서버와 쇼핑몰·제휴망 흉내 조작판, 오른쪽 폰 안은 운영과 같은 적립 화면입니다.
적립 화면/asp/?media=…&sig=…탑툰 앱 안 화면(웹뷰)에 열리는 회원 화면. 서명된 진입 주소로만 열립니다. 주소만 열면 「다시 들어와 주세요」 안내가 나옵니다.
ASP CMS/asp-cms/ · CMS DEMO 「ASP 매체」CMS DEMO 에 관리자로 로그인돼 있으면 실데이터, 아니면 예시 데이터를 보여 줍니다. 전환 재요청, 매체 설정, 쇼핑몰 노출, FAQ, 월간 CSV 가 실제로 저장됩니다.

열람 비밀번호는 다른 데모 문서와 같습니다. 시연 화면에서 만든 기록은 데모 Firestore 에 남고, 「이 회원 기록 지우기」로 회원별로 지울 수 있습니다.

04흐름

  1. 진입 — 탑툰 서버가 서명한 주소로 /asp/ 가 열립니다. 화면이 주소의 ?뒤 문자열을 POST /api/asp/enter 로 보내고, 서버가 서명과 시각(10분)을 검증한 뒤 회원을 만들거나 갱신하고 세션 쿠키를 줍니다. 화면은 주소창에서 서명값을 지웁니다.연동 문서 03 · 05
  2. 쇼핑몰 이동 — 바로가기를 누르면 POST /api/asp/click 이 이동 기록을 남기고 sub_id = asp-{매체코드}-{클릭ID} 를 만듭니다. 링크프라이스는 기본링크에 u_id 로, 쿠팡은 파트너스 딥링크의 subId 로 싣습니다.
  3. 구매 적립 — 포스트백의 sub_id 로 클릭을 찾아 매체 회원 구매로 넣습니다(receiveOrder). 회원에게는 랜덤 티켓 1장으로 보이고, 장수는 확정 전까지 내보내지 않습니다. 같은 주문번호는 한 번만 적립합니다.
  4. 확정 — 확정 기준일에 confirmOrder 가 구매할 때 남긴 적립률과 티켓 1장 값으로 장수를 정해 확정 티켓에 더합니다. 취소·반품은 missOrder.
  5. 전환 — 회원이 「코인으로 전환」을 누르면 POST /api/asp/convert. 전환 단위만큼 티켓을 보류하고 거래번호를 만든 뒤 탑툰 코인 지급 API 를 부르고, 결과대로 차감 확정 · 되돌림 · 재시도로 나눕니다.연동 문서 04 · 06
  6. 재시도 — 응답이 없거나 9999 면 같은 거래번호로 1분 · 5분 · 30분 뒤 다시 보냅니다. 세 번 모두 실패하면 운영자 확인으로 넘기고, 운영자가 CMS 「다시 보내기」로 같은 거래번호를 보냅니다.
  7. 월간 대조 — CMS 에서 월을 골라 지급 내역 CSV 를 내려받아 탑툰에 전달합니다.연동 문서 07

07규칙

항목값
진입 유효 시간ts 와 서버 시각 차이 10분 이내. 서명은 sig 를 뺀 모든 파라미터를 키 오름차순으로 이은 문자열의 HMAC-SHA256
세션6시간. 서명 쿠키(HMAC). 진입 주소의 서명값은 다시 쓰지 않음
적립 인정이동 후 24시간 안 구매. 같은 주문번호는 한 번
확정 예정일쿠팡 구매일 + 7일, 그 외 구매한 달의 다다음 달 6일 (KST)
티켓 장수내림(구매 금액 × 적립률% ÷ 티켓 1장 값). 적립률과 1장 값은 클릭할 때 값으로 고정. 적립률이 없는 몰은 매체 기본 적립률
회원 표시확정 전은 「랜덤 티켓 1장」, 장수 비공개. 확정 뒤 장수 공개
전환내림(확정 티켓 ÷ 전환 단위)개, 전환 단위 × 개수만큼 보류. 처리 중 전환이 있으면 새 전환을 막음
거래번호PPT + KST 날짜 8자리 + 날짜별 일련번호 6자리 (예: PPT20261016000123)
결과 처리0000 차감 확정 · 1001 1002 2001 2003 실패 확정·티켓 되돌림 · 2002 새 시각으로 그 자리에서 한 번 더 · 9999 와 10초 무응답 재시도
재시도1분 · 5분 · 30분 뒤 같은 거래번호로. 세 번 모두 실패하면 운영자 확인(티켓은 보류 그대로, 새 전환은 허용)
동시 처리 막기전환을 보내기 전에 25초 동안 잡아 둠(lease_until). 다른 곳에서 같은 전환을 동시에 보내지 않음

08운영 전환 때 바꿀 것

항목데모운영
1포스트백시연 화면의 「구매 완료 (데모)」가 흉내기존 포스트백 수신기에서 sub_id 가 asp- 로 시작하면 receiveOrder 로 넘김. 포스트백 로그에 매체 열 추가
2확정 · 미적립「적립 예정 전부 확정」 버튼확정 기준일 배치가 confirmOrder · missOrder 호출 (쿠팡 구매 확정, 링크프라이스 확정 데이터)
3재시도 스케줄러화면 조회 때 같이 + 「재시도 대기 건 지금 보내기」 (Vercel Hobby 는 분 단위 스케줄러 없음)1분마다 retryDue 를 부르는 스케줄러
4연동 토큰연동 문서 05 의 예시 토큰ASP_TOKEN_TOPTOON 운영·시험 따로, ASP_ALLOW_TEST_TOKEN=off
5세션 비밀값서비스 계정 값에서 끌어냄ASP_SESSION_SECRET 따로
6데모 장치켜짐ASP_DEMO=off — 흉내 서버가 닫히고, 회원 화면의 데모 시트 대신 제휴 주소로 이동
7코인 지급 API 주소/api/asp-mock/coin탑툰이 회신한 운영·시험 주소를 asp_media.coin_api_url 에
8쿠팡 이동 주소만들지 않음쿠팡 파트너스 딥링크 API 를 subId = sub_id 로 불러 받은 주소
9홈 화면 바로가기화면만 (휴대폰 홈 화면 흉내)탑툰 앱의 바로가기 기능 연동이 필요 — 탑툰과 협의
10적립 한도적용 안 함프라이스픽 앱의 일 5장 · 월 50장(랜덤 티켓 기준)을 ASP 에도 둘지 결정 필요
11적립률앱 적립률, 없으면 매체 기본 0.5%매체별로 따로 둘지 결정 필요
12CMS DEMO 쪽 수정—ASP CMS 「CMS DEMO 연동」 화면의 「CMS DEMO 수정 필요」 항목(매출 유입 경로, 어뷰징 감시, 관리자 권한 등)

연동 문서 08 의 8가지는 시연 화면에서 이렇게 재현합니다.

시험 항목시연 화면에서
